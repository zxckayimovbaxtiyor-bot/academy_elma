# Практика: реализация и эксплуатация

Дата: 22 октября 2026 года. Модуль добавлен в существующую LMS; прежние курсы,
сертификаты, публикации ElmaRelease, авторизация, оформление и RU/UZ сохранены.

## Архитектура

Канонический документ сценария — JSONB с типизированной Pydantic-схемой v1.
Сценарий связан с модулем и необязательным уроком. Экраны и правила представлены
`PracticeScreen` и `PracticeRule` в `app/schemas/practice.py`, внутри версии:
отдельные реляционные копии этих объектов не создаются.

Поддерживаются 15 типов компонентов: button, text, number, select, table, tabs,
checkbox, modal, document, client, status, notification, image, hint, transition.
React renderer имеет реестр компонентов; расширение требует добавить разрешённый
тип в серверную схему и renderer. Старые сценарии при этом не меняются.

Движок сравнивает только значения: eq/ne, gte/lte, present, in. Переходы содержат
списки условий AND; несколько переходов одной кнопки образуют последовательные
ветви. Побеждает первая подходящая ветвь. Скриптов, SQL, HTML и сетевых действий
в сценариях нет. Ссылки на экраны, поля, начальный/итоговый экран, достижимость
и возможность дойти до завершения проверяются сервером. Определение ограничено
256 КБ; до 50 экранов, 50 компонентов и 50 правил на экран.

Сессия фиксирует версию сценария, вариант индивидуального задания, выпуск
учебного модуля и политику оценки. Публикация следующей версии не переписывает
текущую сессию. Новые попытки используют последнюю опубликованную версию.
Черновик редактируется с expected_revision. Для публикации обязателен
предпросмотр именно этой ревизии; изменение черновика сбрасывает отметку.
PostgreSQL trigger запрещает UPDATE/DELETE уже опубликованной версии.

## Таблицы и миграции

- `practice_scenario` — модуль, урок, автор.
- `practice_scenario_version` — номер, ревизия, JSONB, отметка предпросмотра,
  дата и автор публикации; единственный черновик на сценарий.
- `practice_assignment` — политика, действующая для назначенных модулю людей.
- `practice_session` — владелец, версия, режим, выпуск, состояние, ревизия,
  политика на старте, время начала/окончания; одна активная сессия каждого режима.
- `practice_action` — request_id, хеш команды, экран, ошибки, сохранённый ответ.
- `practice_result` — единственный серверный результат сессии, балл, успех,
  длительность и ошибки.
- `practice_asset` — разрешённый синтетический скриншот, привязанный к сценарию.

`0002_practice.py` создаёт семь новых таблиц, индексы, FK и trigger.
`0003_practice_workspace.py` расширяет поле вида операции в журнале.
Старые данные миграции не изменяют. Перед промышленным обновлением сделайте
обычную резервную копию PostgreSQL. Выполните `alembic upgrade head`.
Downgrade удаляет только новые таблицы, но вместе с историей практики: для отката
с данными используйте резервную копию. Проверка downgrade/upgrade выполняется
только в отдельной БД с окончанием `_test`.

## API

Все пути ниже начинаются с `/api/v1`.

Сотрудник (`current_user`, назначение модуля, Core и разрешённая роль):

- `GET /me/practices?module_id=&lesson_id=` — доступные сценарии и история попыток.
- `POST /me/practices/{id}/sessions` — `{mode: guided|exam}`, запуск/возобновление.
- `GET /me/practice-sessions/{id}` — восстановление, текущий экран и значения.
- `POST /me/practice-sessions/{id}/commands` — сохранение/действие/назад/сброс/
  завершение.
- `GET /me/practice-sessions/{id}/actions` — журнал без скрытых правил проверки.
- `GET /me/practice-sessions/{id}/result` — результат после завершения.
- `GET /practice-assets/{id}?session_id=` — изображение с проверкой принадлежности
  собственной сессии и версии; автора проверяет серверная роль.

Автор (`admin` или `methodologist`):

- `GET /admin/practices` и `GET /admin/practices/{id}` — сценарии и рабочая версия.
- `GET /admin/practices/template` — двуязычный пример кредита.
- `POST /admin/practices` — создание с module_id, lesson_id, definition.
- `PUT /admin/practices/{id}/draft` — definition и expected_revision.
- `POST /admin/practices/preview` — начальный экран проверенного определения.
- `POST /admin/practices/preview/step` — исполнение в неперсистентном предпросмотре.
- `POST /admin/practices/{id}/preview` — проверка ревизии перед публикацией.
- `POST /admin/practices/{id}/publish` — публикация проверенной ревизии.
- `PUT /admin/practices/{id}/assignment` — учебная политика.
- `PUT /admin/practices/{id}/screenshots?synthetic_data_confirmed=true` — raw PNG/JPEG.

Отчёты (`admin` или `branch_head`):

- `GET /reports/practice` — module_id, user_id, branch_id, job_role_id, wave_id,
  region_id, mode, page, page_size (1–100, по умолчанию 50). Филиал руководителя
  принудительно применяется сервером, независимо от фильтров запроса.

Команда содержит request_id (8–80 символов), expected_revision, kind,
необязательные action, target и values. Передаются только изменяемые поля
текущего экрана. Ответы содержат новую revision. Тот же request_id с тем же
запросом возвращает исходный ответ; другое содержимое даёт 409. Устаревшая
ревизия даёт 409 и требует перечитать сессию. Запуск сериализуется блокировкой
пользователя; изменение — блокировкой сессии. Всё фиксируется одной транзакцией.

## Инструкция методологу и администратору

1. Откройте **Админ-панель → Практика**.
2. Выберите **Новый сценарий** либо **Пример: потребительский кредит**.
3. Заполните название и описание RU/UZ, выберите модуль и необязательный урок.
   Привязка фиксируется при создании; доступ сотрудников наследуется от LMS.
4. Добавьте экраны, их двуязычные названия и компоненты. Стрелки вверх/вниз
   меняют порядок компонентов и работают с клавиатуры.
5. У списков заполните значения вариантов и RU/UZ подписи. У кнопок задайте
   переходы; при необходимости добавьте условия. Схема показывает связи.
6. Добавьте правила: поле, оператор, ожидаемое значение, объяснение ошибки
   RU/UZ и штраф в баллах из 100. Правила должны ссылаться на существующее поле.
7. При необходимости раскройте индивидуальные задания: задайте варианты
   описания и ожидаемых значений. У связанного правила включите значение из
   задания. Экзамен выбирает вариант на сервере, обучение использует первый.
8. Для скриншота сначала сохраните сценарий, затем добавьте изображение.
   Подтверждение синтетических данных находится у выбора файла. Добавьте
   области в процентах x/y/ширина/высота и свяжите их с кнопками этого экрана.
9. Сохраните валидный черновик. Откройте интерактивный предпросмотр, проверьте
   переходы и ошибки, закройте окно и опубликуйте.
10. Настройте обязательность, режим зачёта (успех или завершение экзамена),
    балл, лимит попыток, повторение, повтор после обновления сценария/материала,
    необходимость сначала закончить видео, барьер перед тестом/сертификатом.
    Сохраните настройки отдельной кнопкой.

Редактирование опубликованного сценария создаёт следующий черновик. Действующая
публикация остаётся доступной, пока не опубликована новая. Черновики должны
проходить проверку структуры и связей; незаполненные RU/UZ поля не сохраняются.

## Инструкция сотруднику

Откройте **Практика** в меню или карточку практики в своём модуле/уроке.
Выберите режим:

- **Обучение:** подсказки, подсветка кнопок, объяснения ошибок и возврат назад.
- **Экзамен:** индивидуальное задание, без подсказок и возврата. Неправильное
  действие регистрируется; данные можно исправить, но штраф сохраняется.

Изменения формы сохраняются через 1,2 секунды без ввода; есть отдельная кнопка
сохранения. Дождитесь отметки сохранения. После
обрыва сети повторяется тот же запрос. Завершение доступно на итоговом экране.
Журнал действий и предыдущие попытки доступны из интерфейса.

Экзамен оценивается как `max(0, 100 − сумма уникальных штрафов)`.
Пропуск обязательного поля стоит 5 баллов, авторские правила задают 1–100.
Повтор одного и того же нарушения в том же экране не множит штраф и не скрывает
последующие ошибки. В обучении завершение даёт 100; для обязательного
зачёта учитывается только экзамен. Финальный экран также проверяет свои поля.

## Интеграция с сертификацией и отчётами

По умолчанию практика необязательна и не блокирует старые модули.
Барьер `before_test` включается в существующую eligibility проверки теста.
При `before_certificate` успешный тест сохраняется, а сертификат выдаётся после
выполнения практики; затем применяется существующая оценка операторского
сертификата. Уже выданные сертификаты не отзываются и не пересчитываются.
Повтор после обновления влияет на новые проверки требований, сохраняя историю.

Блок аналитики добавлен в общий отчёт и карточку сотрудника. Он показывает
старты, завершения, долю успешных попыток, среднее время, повторы, ошибки,
этапы, филиалы, должности и людей. По умолчанию выбран экзамен. Пагинация
деталей не меняет общие показатели. Запрос не загружает полные состояния
учебных сессий и снимки ответов действий.

## Демо и запуск

Демонстрация кредита содержит 10 экранов: начало, кредитование, поиск,
карточка, создание заявки, сумма/срок, документы, проверка, отправка, итог.
Три варианта: 12 млн/12 месяцев, 8 млн/6, 15 млн/18. Все клиенты и документы
имеют учебные идентификаторы. Ошибки включают другого клиента, продукт,
сумму/срок, просроченный документ и пропуск обязательного подтверждения.

В существующей среде с настроенным DATABASE_URL:

```sh
cd backend
python -m alembic upgrade head
python -m app.cli seed --practice
```

Нужен существующий admin. Команда добавляет пример в Core, привязывая к первому
уроку при наличии. Повторный запуск сохраняет существующий сценарий. `seed --demo`
также добавляет практику. Промышленный seed не меняет роли и пароли.

На подготовленной Windows установке: `.\start-local.ps1`. Основной адрес:
`http://127.0.0.1:5173/practice`; конструктор — `/admin/practice`.
Локальные временные реквизиты — `.local/credentials.json`; они не входят в Git.

## Безопасность и границы

Используются существующие сессии, смена временного пароля, CSRF, no-store,
RBAC и серверные назначения. Каждый доступ к сессии и изображению проверяется
заново. Правила, ожидаемые значения и hints не возвращаются экзамену.
Оценка, состояние, статус и владелец не принимаются из браузера. Важные действия
записываются в прежний AuditEvent; все операции сессии — в PracticeAction.

Изображения: до 2 МБ исходных PNG/JPEG, до 8 млн пикселей; сервер перекодирует
их в PNG без метаданных. SVG/HTML и внешние URL не поддерживаются. Учебный
документ выбирается из синтетических ресурсов сценария: произвольные реальные
документы сотрудника не загружаются. Проверка отсутствия реальных ПДн в
содержимом остаётся обязанностью автора материалов.

Практика не обращается к ELMA365 или другим банковским системам. Интерфейс
нейтральный: исходные разрешённые скриншоты ELMA365 не предоставлены.
Drag-and-drop не добавлялся; доступны устойчивые клавиатурные элементы.
В одной сессии ограничено 2000 изменяющих команд. Аналитика получает данные
в текущем запросе; фоновых витрин и нагрузочных измерений пока нет.

изоляцию, попытки, повторные команды, конфликты ревизий, подмену результатов,
повреждённые определения и состояние предпросмотра, индивидуальные варианты,
несколько заявок, фильтры/пагинацию, оба барьера сертификации и совместимость
со старыми модулями. Проверен цикл миграций 0003 → 0001 → 0003 на тестовой БД.

`alembic check`: **No new upgrade operations detected** — модели соответствуют
миграциям. Повторный `seed --practice` сохранил существующий пример без изменений.
`npm run build`: **успешно**, включая TypeScript, 10 тестов Frontend,
проверку 1028 ключей RU/UZ (338 динамических ссылок) и Vite production build.
`git diff --check`: ошибок нет.

БД не подключалась. Миграции применены и на локальной учебной `academy`.

В браузере с настоящим API проверены RU/UZ, запуск, обязательные поля, ошибка
другого клиента, просроченный документ, исправление, полный цикл, серверный
результат, восстановление после reload, создание второй виртуальной заявки
и возврат к сохранённой первой. Консоль ошибок не показала.
В настоящем отчёте руководителя филиала проверены переключение режима,
раскрытие аналитики и отображение завершённого результата 100% с двумя
зарегистрированными ошибками обучения.

Конструктор проверен в браузере на отдельном стенде с ответами в памяти:
редактирование RU, сохранение, интерактивные переходы предпросмотра,
разблокирование публикации и публикация. Стенд не подключён к основной БД,
не создаёт пользователей и привилегии. Реальный API конструктора, RBAC,
публикация и PostgreSQL проверены автоматическими интеграционными тестами.
Создание дополнительного привилегированного тестового аккаунта автоматическая
проверка отклонила; оно не выполнялось.

Подтверждённый браузерный viewport — 1280×720. Переполнение верхнего меню и
кнопок практики устранено. Попытка установить 390×844 не изменила реальный
viewport инструмента, поэтому проверка на телефоне не заявляется.
Docker отсутствует: Compose-сборка не запускалась. Перед промышленным вводом
нужны проверка Docker/nginx, мобильных браузеров и нагрузочная проверка на
ожидаемом объёме истории. Рекомендуется последующий прогон доступности и
приёмка методологом на разрешённых скриншотах и реальных учебных регламентах.
