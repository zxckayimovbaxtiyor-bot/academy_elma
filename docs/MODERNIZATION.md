Дата: 21 октября 2026, Asia/Tashkent. Работа ведётся в существующем проекте.
База и медиа сохраняются. Стек, логотип, палитра и правила оценивания остаются.

- React 18, TypeScript, Vite; отдельная ленивая загрузка административной панели и HLS-плеера.
- FastAPI, SQLAlchemy, Alembic, PostgreSQL 16; 25 таблиц в исходной миграции.
- Четыре роли; Argon2id, временные пароли, блокировка входа, хешированные сессии,
  обязательная смена временного пароля, CSRF-заголовок, отзыв сессий.
- Назначение модулей по роли и волне филиала, Core как предварительное условие.
- Версии уроков, черновики и публикация релизов, HLS, узбекские/русские субтитры и PDF.
- Проверка 90% просмотра на сервере с блокировкой строки прогресса.
- Четыре типа вопросов, случайный пул, серверное оценивание, таймер, попытки,
  идемпотентная отправка результата под блокировкой строки, повторное изучение ошибок.
- PDF/QR-сертификаты, публичная проверка с кодом, повторная сертификация.
- Отчёты, фильтры, CSV, импорт сотрудников, волны и банк вопросов.
- Очередь задач PostgreSQL, две линии worker, восстановление после прерывания.
- AI-черновики опциональны и требуют проверки методологом.

Новые аналоги этих механизмов создавать не требуется.

## Находки и приоритеты до исправлений этапа 1

### P1 — доступ к файлам проверяет только факт входа

`app/api/system.py`, `nginx/nginx.conf`, `backend/local_server.py`.
API уроков проверяет назначение и Core, но прямая ссылка `/media/...` этих проверок
не выполняет. Зная URL, любой вошедший сотрудник может запросить чужой продукт,
черновик или изображение из банка вопросов. Случайное имя файла не является проверкой прав.

Исправление: единая серверная проверка конкретного ресурса, опубликованной версии,
назначения, предварительного условия и принадлежности вопроса попытке сотрудника.
Администратор и методолог сохраняют предпросмотр.

### P1 — положительный результат авторизации медиа кэшируется

nginx кэширует разрешение на 60 секунд только по cookie, а медиа разрешено
кэшировать в браузере сутки. После выхода/деактивации ранее разрешённая загрузка
может обходить немедленную проверку сессии. Нужны проверка каждого запроса
и `Cache-Control: no-store` для защищённых ответов.
Уже скачанные клиентом данные отозвать технически невозможно.

### P1 — чтение тела некоторых загрузок предшествует авторизации

`body_reader` принимает PDF/изображения/CSV/субтитры до зависимости роли.
Неавторизованный запрос может заставить приложение прочитать до лимита файл.
Для видео предварительная проверка уже есть. Нужна аналогичная ранняя
проверка прав для остальных потоков без изменения формата API.

### P1 — общие пароли БД в конфигурации Compose

Fallback `academy` разрешает запуск без индивидуального пароля. Убрать fallback,
сделать пароль и публичный адрес обязательными. Подробная HTTPS-конфигурация — этап 2.

### P2 — совместимость Windows и фонового запуска

Проверка i18n использовала URL.pathname вместо fileURLToPath; Python не получал
IANA timezone database; PostgreSQL наследовал часовой пояс ОС, что меняло
сериализацию повторного ответа. Добавлены Windows timezone data и локальный UTC.
Проверена отдельная остановка и повторный запуск с сохранением данных.

### P2 — производительность и эксплуатация, следующие этапы

- `_path` получает release code отдельно для каждого модуля: небольшой N+1.
- Отчёт пользователей загружает все строки и только потом режет страницу в Python.
- Список банка вопросов возвращается целиком; нужна совместимая пагинация.
- Worker хранит repr непредвиденного исключения и пишет traceback: нужна политика
  редактирования потенциально чувствительных подробностей и контролируемые коды ошибок.
- PDF/PNG/JPEG проверяются преимущественно по сигнатуре. Требуется полноценная
  проверка содержимого/размеров и оценка необходимости изолированного сканирования.
- HTTPS, HSTS, лимит запросов входа на уровне nginx, проверка production-настроек,
  health worker, резервное копирование и восстановление требуют отдельной проверки.
- Интерактивные симуляции и блочные текстовые уроки в коде не реализованы.
- Текущий интерфейс уже имеет дизайн-токены, адаптивность, ошибки/пустые состояния,
  прогресс, приветствие, сроки и продолжение. Улучшать существующее, не дублировать.

## Последовательность реализации

1. **Аудит и критические исправления:** права на каждый media-ресурс, немедленная
   проверка сессий, ранняя авторизация загрузок, обязательный пароль БД,
   воспроизводимый запуск, регрессионные тесты. Без изменений схемы данных.
2. **Безопасность и backend:** отдельная HTTPS-конфигурация, проверка настроек,
   сессии и лимиты, проверка файлов, безопасные логи, устойчивость worker.
3. **Frontend и дизайн-система:** сохранить бренд, улучшить компоненты,
   skeleton/доступность, загрузку страниц и работу на слабых устройствах.
4. **Кабинеты:** обновить главную и админпанель на реальных API, уведомления,
   массовые действия и подтверждения с серверными проверками.
5. **Конструктор и тесты:** расширяемые блоки текста/изображений/PDF/шагов,
   предпросмотр и публикация версий; сохранить все правила оценивания и просмотра.
6. **Симуляции:** версия JSON-сценария, серверная валидация шагов и прогресса,
   редактор для администратора и один полный сценарий с учебными данными.
   Новые сущности добавлять только миграциями. Реальных банковских подключений нет.
7. **Аналитика и производительность:** SQL-пагинация/агрегации, индексы по планам
   запросов, средний балл, завершённые уроки, сложные темы и интерактивные графики.
8. **Проверка и документация:** все тесты, новые регрессии, frontend build,
   миграции на копии, Docker/HTTPS и проверка восстановления резервной копии.

Каждый этап заканчивается проверками совместимости и отдельным перечнем изменений.
Этапы 2–8 этим первым проходом не объявляются выполненными.
